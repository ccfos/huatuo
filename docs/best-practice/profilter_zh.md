本文说明折叠栈和火焰图的格式与解读方法。采集、存储和任务完成条件见[性能剖析实践](/docs/best-practice/continuous-profiling_zh.md#结果)。

HUATUO 的 `profiler` 与 `irqtracing` 使用同一窗口格式化器。样本单位取决于采集模式：CPU 时间为纳秒，内存为字节，IRQ 事件为次数。解读数值前，应先确认采集模式和单位。

## 选择格式

| 目标 | 格式 | 说明 |
| --- | --- | --- |
| 脚本聚合、过滤或重新渲染 | `collapsed` | 每行包含调用栈和样本值 |
| 在浏览器中查看调用路径 | `flamegraph`、`svg` | HUATUO 输出带交互脚本的 SVG |
| 保留窗口、标签和完整符号 | `json` 或 pprof 兼容数据 | 避免折叠栈的名称规范化损失 |

## 折叠栈

### 行格式

Collapsed（也称 folded stacks）以分号分隔栈帧，以空格分隔调用栈与末尾数值：

```text
frame1;frame2;frame3;...;frameN COUNT
```

| 部分 | 含义 |
| --- | --- |
| `frame1` | 根帧，如 `main`、`start_thread` |
| `;` | 栈帧分隔符 |
| `frameN` | 叶帧 |
| `COUNT` | 此调用栈的累计样本值；单位由采集模式决定 |

栈帧从左到右按根到叶排列。相同调用路径的值可聚合；比较前需确认采集模式、单位、目标和时间范围一致。

### 帧名称

折叠栈没有统一的转义规则。HUATUO 将帧名中的 `;` 替换为 `:`，将回车和换行替换为空格，确保每条调用栈只占一行。内部符号及结构化格式保留原始名称。

例如，`generic::<[u8; 7]>` 输出为 `generic::<[u8: 7]>`。只在 `;` 和 `:` 上不同的符号会合并；需要保留完整符号时，应使用结构化格式。

### 数值示例

以下为 CPU 时间折叠栈示意，末尾数值的单位为纳秒，不表示采样次数：

```text
main;handle;read 2000000
main;handle;parse 1000000
```

两条调用路径分别累计 2 ms 和 1 ms。在这组数据中，`handle` 的累计值为 3 ms，`read` 路径占三分之二。内存和 IRQ 模式应分别按字节和次数解读。

## 火焰图

| 维度 | 含义 |
| --- | --- |
| 横向位置 | 调用路径的排列，不表示时间先后 |
| 纵向位置 | 调用深度，通常底部为根帧、顶部为叶帧 |
| 帧宽度 | 所选观测维度的累计值及占比 |
| 帧颜色 | 由渲染工具决定，不能跨工具直接比较 |

较宽的帧表示在当前观测维度中占比较高，不单独证明瓶颈或故障根因。比较优化前后的结果时，需保持负载和采集条件可比。

HUATUO 的 `flamegraph` 与 `svg` 输出等价，均为带交互脚本的 SVG。可通过缩放、搜索和悬浮提示定位调用路径、查看数值。

分析时先确认采集模式和单位，再查看占比较高的调用路径，并结合其他观测判断原因。保留折叠栈可用于重新渲染和聚合；需要完整符号、窗口或标签时，保留结构化结果。
